# Miowser local video library optimization plan

November 9, 2026 · Next Player 0.20.0 and VLC Android 3.7.2

Use Android’s MediaStore as the first source for device videos, following Next Player. Use a small, indexed Miowser catalog for device videos and linked folders, with durable saved media and watch state kept separately. Take VLC’s bounded page loading and staged enrichment as the model for large collections. The existing rich player can open the resulting media IDs and content URIs.

## Hub structure

| Tab | Purpose |
| --- | --- |
| **Device Videos** · primary | Open the local video library by default when the new Hub ships. Use MediaStore and explicitly linked folders. Show cached results while discovery runs and provide a clear permission or empty state where needed. Launch playback in the existing rich player. |
| **Miowser Hub** · secondary | Keep the existing saved Library, downloads, browser access, and Hub settings together. Preserve saved media, folder structure, progress, and backup behavior through migration. |

P0 measures the current saved Library. P1 and P2 can migrate and page that data before P3 exposes the primary device-video tab. At that point, run the same journeys against both tabs, plus a tab-switching journey. Measure local launch independently from the secondary Hub’s browser and download work.

The P0 emulator run verified the benchmark harness. The physical-device measurements were waived before P1. P1 migrated the saved Library to Room and kept the existing backup format. P2 added indexed browsing, a bounded page window, and playlists that span pages. [P1 release notes](G:/Projects/Miowser/docs/RELEASE_NOTES_0.1.53.md) · [P2 release notes](G:/Projects/Miowser/docs/RELEASE_NOTES_0.1.54.md)

P3 adds Device Videos as the primary tab and keeps Miowser Hub as the second tab. Its separate Room catalog reconciles mounted MediaStore volumes, linked folders, and completed downloads. [P3 release notes](G:/Projects/Miowser/docs/RELEASE_NOTES_0.1.55.md)

P4 shares regenerable local previews across Device Videos, Downloads, and local Library frame generation. A bounded queue prioritizes visible requests and limits frame extraction to one at a time. [P4 release notes](G:/Projects/Miowser/docs/RELEASE_NOTES_0.1.56.md)

## How Next Player builds the library

| Layer | Observed behavior | Implication for Miowser |
| --- | --- | --- |
| Discovery | A single shared `ContentObserver` watches the video collection. The tagged implementation debounces bursts by 250 ms, queries on IO, replays the last invalidation, and stops observing after a subscriber grace period. The projection requests ID, path, display name, dimensions, duration, size, and timestamps. It builds folder views from paths. | A video can appear with a name, duration, and dimensions before any frame decode. Treat notifications as signals to reconcile, with one observer per active catalog scope. |
| Storage | The current Room schema contains `media_state`, `hidden_video`, `network_connection`, `playlist`, and `playlist_item`. The shipped schema does not contain a table mirroring the entire public device-video catalog. The repository joins MediaStore videos to per-URI Room state using a map. | Keep durable playback state and user organization separate from indexed file metadata. A seek or track change should update one state row. |
| Sort, folders, and UI | The tag builds folder and video lists from the queried rows. The tree use case sorts and projects them off the UI thread. Compose’s lazy grid uses folder paths and video URIs as keys and reserves artwork space. The data path still materializes query results and combines lists. | Borrow stable keys, lightweight rows, and placeholders. For very large collections, apply filtering and ordering in the catalog query and page the results. |
| Thumbnails | Visible local video cards request Coil images. The decoder looks in the disk cache, checks whether the cached dimensions satisfy the request, and decodes on a miss. It tries embedded art and Android frame extraction with a NextLib/FFmpeg fallback. The tag offers first frame, percentage, and hybrid selection. It resizes to the requested dimensions and commits a JPEG through the cache editor. | One request and cache pipeline can serve grid, list, and download rows. Include source revision and size in keys, and budget concurrent decodes. |
| Cache lifetime | The tagged singleton loader keeps its thumbnail disk cache in `filesDir/thumbnails` and requests a size based on free disk space. Exact effective bounds depend on the bundled Coil implementation. The decoder defaults to a URI or file path as its disk key, with an explicit request key override. | Adopt explicit byte limits and stale-artwork invalidation for Miowser, which shares memory with WebViews and a playback engine. |
| Reconciliation | The synchronizer checks storage permission before pruning missing local playlist entries, playback state, associated thumbnails, and unused subtitle grants. It handles a failed query separately from a successful empty result. The tag also handles a volume disappearing during a query. | Keep history and manual organization when a volume unmounts, a folder grant expires, or Android exposes a smaller selection. Scope reconciliation to the source that completed. |

APK anchors include `ap5.a` at DEX file offset `0x5b9830` for schema creation, `qn7.r` at `0x6e1b88` for the observer path, and `f50.b` at `0x2648d0` for Android and NextLib frame extraction. Room stores playback position, selected tracks, external subtitle and audio references, video scale, and subtitle timing by URI. Local playlist items have a playlist and URI key plus an ordered position. The native retriever and FFmpeg libraries are present in the APK.

Two implementation details matter at scale. The tagged MediaStore adapter checks filesystem existence while converting rows, and its list projections can rerun after a playback-state update. Miowser can defer individual file opens and isolate progress changes from catalog queries. The tagged missing-volume handler maps a specific provider exception to an empty list, while cleanup checks permission separately. That creates a source-level risk of treating temporary absence as removal. Miowser’s scan result should carry explicit completeness and source-availability states.

## How VLC builds the library

| Layer | Observed behavior | Implication for Miowser |
| --- | --- | --- |
| Startup and discovery | `MedialibraryImpl` initializes a native DB under the app-private DB directory and passes a separate artwork path to native construction. `MediaParsingService` handles discovery, reload and storage events. The tagged source separates scan actions from notifications and includes pause/resume. Native `FsDiscoverer::checkFiles` reads indexed files by parent, checks pause state, updates filesystem information, and calls the changed-file path. | Open existing rows immediately and reconcile separately. Keep each scan scope explicit and cancelable. |
| Native catalog | The ARM64 split ships SQLite inside `libmla.so`. Exported table and index constructors cover media, files, folders, devices, thumbnails, and parser tasks. The Android bridge supports counts, sorted pages, search, favorites, missing items, history and playback position. VLC also has a separate Room database for app data such as custom directories, external subtitles and equalizer entries. | Separate a media item’s stable ID, file location, folder/source membership and playback state. Index each frequent query. Keep missing/offline state separate from deletion. |
| Paging and binding | `VideosProvider.getPage` selects a folder, group, or catalog query and forwards size and offset to the native layer. In the tagged provider, page size is 500, prefetch distance is 100, initial load size is 500, and the configured retained size is 1,000 with placeholders enabled. The RecyclerView adapter computes diffs and applies payloads for changed fields. Callback refreshes are conflated and paused screens can defer invalidation. | Adopt the bounded data window and small row updates in Compose. Choose Miowser’s page size through measurement. VLC’s values reflect its own UI and JNI tradeoffs. |
| Thumbnail hierarchy | `ThumbnailsProvider.getVideoThumbnail` checks a width-qualified memory key and then an on-disk JPEG. On a miss it tries Android thumbnail extraction for file URIs under a lock. An indexed item can request a native frame at 40% when that path yields no usable bitmap. Native `ThumbnailerWorker` and `VmemThumbnailer` symbols confirm a separate thumbnail path. The memory LRU uses one fifth of the Java heap ceiling and weighs entries by pixel bytes. | Serve cache hits first, limit concurrent work, and allow a failure to leave a usable placeholder. The shared WebView and player heap calls for a separate budget in Miowser. |
| Group and folder artwork | Folder and group covers use small sets of member artwork. The video group path asks for up to four members. Playlist artwork keys incorporate the member IDs used for the image, so membership changes can invalidate a composite. | Derive folder covers from a few already available thumbnails. Rebuild when the chosen members or their thumbnail revisions change. |
| Recovery | The APK has explicit native database initialization states, including a corruption path that attempts a clear with playlist restoration. Native exports support storage-device presence and parser task restoration. Tagged code exposes missing-item filtering and distinguishes removed storage from normal list filtering. | A rebuildable catalog should have a separate recovery path from saved entries, play state, and manual folders. Keep the durable user data available during a catalog rebuild. |

## Where Miowser stands

- **Storage and backups.** The P0 store serialized the entire saved collection for every progress write. P1 keeps watch state in its own Room table and exports the existing backup representation for Library records, folders, artwork, and subtitle assets. The saved/manual limit remains 5,000 and recent-play retention remains 500. Device discovery will use a separate catalog. [Library repository](G:/Projects/Miowser/app/src/main/java/com/miowser/app/library/LibraryRepository.kt) · [Retention](G:/Projects/Miowser/app/src/main/java/com/miowser/app/library/LibraryRetention.kt:3) · [Backup format](G:/Projects/Miowser/app/src/main/java/com/miowser/app/backup/BackupArchive.kt:27)
- **Discovery.** The current linked folder import walks a selected SAF tree once. It accumulates its results before publishing. Downloads already retain local URIs and can relink files. Device discovery can build on those capabilities using a separate background catalog. [Folder scanner](G:/Projects/Miowser/app/src/main/java/com/miowser/app/library/ImportedVideoFolder.kt)
- **UI.** The Hub already uses lazy lists/grids, separate structural and progress revisions, a cached projection, and cancellable worker sorting. Each projection still starts with a collection snapshot. Lazy composition limits how many cards appear at once. Query paging would also limit how many records we copy, join, sort, and retain. [Hub projection](G:/Projects/Miowser/app/src/main/java/com/miowser/app/browser/HubHomePage.kt:1569)
- **Artwork.** Miowser already uses versioned JPEGs, a 24 MiB bitmap cache, per-key locks, visible and prefetch paths, an inspection cache, and local/remote midpoint capture. Its executor queues are unbounded at construction. Separate queues and a six-item look-ahead already help. The next step is to bound outstanding requests, unify source identity across surfaces, and account for disk bytes and in-flight decode memory. Preserve the existing poster and remote midpoint behavior and the assets that backups need. [Thumbnail store](G:/Projects/Miowser/app/src/main/java/com/miowser/app/library/LibraryThumbnailStore.kt:33) · [Inspection cache](G:/Projects/Miowser/app/src/main/java/com/miowser/app/library/LocalInspectionCache.kt)
- **Playback entry.** The current queue snapshots visible media identities. A paged Library needs a queue that can cross page boundaries in the selected order. The rich player remains the playback entry point for files and streams. [Playback queue](G:/Projects/Miowser/app/src/main/java/com/miowser/app/player/LibraryPlaybackQueue.kt)

### Catalog and migration decisions

- Store a Miowser media ID, source locator and file revision separately. Use a volume-aware MediaStore identity or SAF provider/tree/document identity when available. Match downloads to an existing row when a proven locator agrees. A moved file with an ambiguous identity should remain relinkable. A filename alone is insufficient for merging records or inheriting watch state.
- Keep a rebuildable discovery catalog apart from durable saved entries and watch state. Index on source and locator, folder and sort key, and last played. Use stable tie-breakers on every ordered query. Keep current search matching semantics during migration and benchmark a full-text index if plain queries become too slow. Start paging at roughly 48–96 lightweight rows and adjust from traces.
- Publish batches transactionally with a source generation. On supported Android versions, compare the MediaStore version before using per-volume generation deltas. Use a stable successful inventory or authoritative removal evidence to mark missing rows. Deltas for added or modified media alone cannot account for deletions. Use a coalesced snapshot fallback on older platforms and when versions change. SAF scans should be scoped and resumable, with a successful end marker before absence is reconciled. [MediaStore reference](https://developer.android.com/reference/android/provider/MediaStore#getGeneration(android.content.Context,%20java.lang.String)) · [Shared media access](https://developer.android.com/training/data-storage/shared/media)
- Preserve explicit saves, user folder membership, watch state, and download linkage when media is inaccessible. Distinguish an empty source, a provider failure, partial permission, a missing grant, and an offline volume. A scan retry should target the affected source. Restore and migration must coordinate with existing write fences so stale jobs cannot resurrect removed items.
- Import legacy data in one verified transaction and retain the old snapshot for recovery through rollout. Make backup export and restore read the active repository before changing the stored format. Keep regenerated device thumbnails out of the durable backup set. Preserve curated/remote assets through the existing asset policy.

### Artwork and UI decisions

- Check the decoded cache and valid thumbnail file before opening a media stream. Use bounded target dimensions and try Android’s available thumbnail path or scaled extraction for local media. A more expensive fallback should follow measurements on files that Android fails to decode. Keep video byte reads separate from rendering and avoid full-file copies for indexing.
- Start with one generation worker on lower-memory devices and a small queue for the visible window. Add short look-ahead for settled scrolling and pause it under playback or memory pressure. Cache failed attempts briefly by source revision. Use atomic file replacement, size-aware keys, and a byte cap with deterministic eviction. Keep regenerable device artwork distinct from existing saved stream artwork.
- Reuse the existing Library folders, grid/list and card metadata. Reserve the same thumbnail space on a cache miss, preserve stable row keys and accessibility, and update artwork independently from position and sort order. With no playback progress sort selected, a watch-position change should update its row without refreshing the ordered catalog. For progress sort, coalesce updates and preserve the visible anchor.
- Keep folder covers derived from a few cached children and store no full video data in the thumbnail cache. A Library scan should make metadata searchable before it has generated the cover for each item.
